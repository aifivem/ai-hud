# ai-hud

The HUD (lumihud-style status pills, money, speedometer, street, voice) and the stress rules. Depends on ai-core (character metadata, money, admin panel), reads pma-voice state when it runs.

## Decisions

- Needs live in ai-core's character metadata (`hunger`, `thirst`, `stress`, 0-100: the QB keys) and ai-core writes all three (owner decision: hunger and thirst, their decay, item effects, start values and the low-needs warnings are ai-core's and tuned in its panel, `ai-core/resource/server/needs/CLAUDE.md`). ai-hud only draws them: the client reads ai-core's player data (`getPlayerData("metadata")` at start, `onPlayerData("metadata")` patches) and sends the NUI only the needs that changed; it shows once ai-core's client says the character is loaded (`IsPlayerLoaded`, `CORE.clientPlayerLoadedEvent` / `clientPlayerUnloadedEvent`).
- Stress rules stay here (`server/stress.ts`): stress only increases from the client (`ai-hud:stress`, 1-5, rate limited; the client sends at most one report per second), which the server passes to lib `stress.gain` (ai-core's stress layer, which writes it while ai-hud is the stress HUD); ai-core's needs pass fades it by `stressRelief` per minute, asked through the export `GetStressRelief()`. Its sources are panel settings: speed above `stressSpeed` km/h with `stressSpeedChance` % per changed speed sample, `stressShot` points per shot (lib `onShot`). Item stress comes through ai-core's item use handling.
- Client values (health, armour, vehicle, street, voice) are read on timers and sent to the NUI only on change; the vehicle timer exists only in a vehicle.
- Server: job labels follow lib `onCharacter` (it also loads the players already in the game after a restart), per-player maps are `PlayerMap`s, settings a `panel.view`.
- The HUD hides without a character, in the pause menu, during screen fades and while a full-screen UI is open (ai-core's `CORE.clientHudVisibleEvent`, lib `hud.onChange`).
- Top right shows the job (the on-duty job, else the first membership, as the bridges pick it) with ai-core's labels, the server id and the character name. The client has no job definitions, so `server/job.ts` resolves the labels from lib `definitions.job`: the client takes a snapshot through the `ai-hud:job` callback at start, the owner gets `ai-hud:client:job` when the shown job changes. Name and id come from ai-core's player data on the client, seeded from its `GetPlayerData` export (after a restart of ai-hud nothing is pushed again).
- Player preferences (`/hud`, the radial menu's HUD entry through ai-core's `OpenHudSettings`): one switch row per HUD part and the key hints in ai-core's menu (lib `menu` `checked` rows, flipped in place), kept in the client's KVP (`client/prefs.ts`, versioned JSON). A panel switch that is off wins; the NUI gets the effective settings. The minimap mode is not a player choice (owner decision).
- Minimap (`Radar` in `client/prefs.ts`): shown while the HUD shows and the panel says `always` (or an admin's `SetMinimapAlways` from ai-admin's menu), else only in a vehicle. `DisplayRadar` is applied on every update (the character screen and the spawn switch it too); the first time it shows after loading, the big map flips on for 200 ms (the minimap otherwise stays empty), never again. The NUI gets `radar` and moves the street / voice / status group beside the minimap or to the left edge (lumihud keeps separate car and on-foot spots). GTA's health / armour bars under it are hidden by calling the minimap scaleform's `SETUP_HEALTH_ARMOUR` with 3 every frame while it shows. In a vehicle `SetRadarZoom(minimapZoom)` runs on each 250 ms visibility update (the game resets the zoom as the vehicle moves; values up to 1400 work although the native docs say 200); leaving the vehicle, a 0 setting or the resource stopping sets 0 (the game's zoom).
- Waypoint colour (`client/waypoint.ts`): the panel's `waypoint.color` replaces HUD colour 142 (`HUD_COLOUR_WAYPOINT`, blip and GPS route; game default 164,76,242) with `ReplaceHudColourWithRgba`; the colour read with `GetHudColour` before the first replace comes back when `waypoint.custom` is switched off or the resource stops. Applied from `Hud.setup()` only when the value changed.
- Key hints on the left: ai-core's list (`KEY_HINTS` event, `GetKeyHints()` at start) forwarded to the NUI unchanged, drawn as lumihud's help buttons (icon circle + pill with key and label; icon names map in `web/src/features/KeyHints.tsx`, unknown ones draw a keyboard); the panel's `keyHints` switch and the player's preference turn them off.
- Weapon box (top right under the money, `client/weapon.ts`): while a weapon is held, the label and picture come from lib `inventory.currentWeapon()` (ai-core's inventory layer, whatever inventory runs), read on each weapon change; the rounds from natives every 250 ms, sent only on change; no clip = label only.
- Key hint texts are the keybinds' short `hintLabel` (one or two words); the long description stays for GTA's key settings.
- Speedometer copies lumihud's Type1 car gauge: the drop shadow sits only on the arcs and the digits, the belt and fuel icons share the right column (top and bottom).
- Voice: pma-voice range from its player state `proximity.index` (lib `PlayerState` mirror) at start, then its `setTalkingMode` / `radioActive` events; the NUI gets a voice message only when talking, range or radio changed.

## Contracts

- Events: `resource/common/hud.ts`. Client exports `OpenSettings()`, `SetMinimapAlways(on)`, `GetMinimapAlways()`; command `hud`. Server export `GetStressRelief()` (ai-core's stress layer). Hunger and thirst for other scripts: lib `needs` (ai-core).
- Listens to ai-core's `playerLoaded` / `playerUnloaded` / `jobsChanged` / `dutyChanged`; reads `GetJobs`, `GetDutyJob`, `GetJobDefinitions` only when the shown job may have changed.
- Reads the vehicle state bag `VEHICLE_BAGS.fuel` (a fuel script sets it), the player bag `PLAYER_BAGS.proximity` (pma-voice / ai-voice range), the seat belt through lib `seatbelt` (ai-core's seat belt layer: `isOn()` on vehicle entry, `onChange`) and pma-voice's local events.

## Entry points

- Stress rules: `resource/server/stress.ts`; panel `server/schema.ts`.
- Job labels: `resource/server/job.ts`.
- Client: state `resource/client/hud/state.ts`, its events and visibility `client/hud/index.ts`, watcher start order `client/start.ts`, value watchers `client/watchers.ts`, name and job `client/identity.ts`.
- NUI: `web/src/features/Hud.tsx` (status row `Status.tsx` / `Needs.tsx` / `Voice.tsx`, name and money `TopRight.tsx`); browser preview `bun run webdev` (`?vehicle=1&radio=1&offduty=1`).
